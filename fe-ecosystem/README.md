# Frontend Platform & AI Software Factory
## Blueprint v4.1 — Target design and AISF Frontend Profile 1.1

**Date:** 2026-11-23  
**Status:** Target Architecture & Operating Model, and **AISF Frontend Profile 1.1**. Technology choices are **proposals** (default ADRs), **not yet settled decisions**; they are confirmed through spikes in Phase 0 ([§17](17-decisions-to-make.md#s17)). Numbers marked *suggested* are proposed targets; numbers marked *baseline* MUST be measured before a target is set. Both are settled in Phase 0 or once data is available.  
**Owner:** Frontend Platform Owner, who is also the owner of the Frontend Profile  
**Scope:** The entire frontend layer of a cloud ecosystem: User Portal (Console), Admin Portal, Service Desk (ticket), Content Studio (CMS), Public Website/Landing, Docs Portal, Chat AI, Document Management, Design System and every product that emerges later  
**Conformance:** **AI Software Factory Standard 4.0** (pinned at `aisf@4.0.0`) and its vocabulary [`aisf-vocabulary.yaml`](../ai-software-factory/aisf-vocabulary.yaml). The conformance claim is in [§18](18-aisf-conformance.md#s18). Target levels: pilot claim (L1 plus the pilot's list of CORE-IDs) for Slice 0, which is the AISF pilot on one Console surface; L2 for generator-created repos, from the moment of creation, starting at the end of Phase 1b; L3 for Wave 1 repos by the end of Phase 2; L4 for at least one surface in Phase 6.  
**Role:** Showcase of the Standard. Every core requirement this profile claims conformance with is demonstrated by a runnable scenario ([§20](20-showcase.md#s20)).  
**Design stance:** Design for the **target state**, as if building from scratch. Existing systems do **not** constrain design choices. They are used only as (1) **evidence of the problem** to be solved ([§0.1](00-summary.md#s0-1)) and (2) **data** to calibrate the Factory ([§16](16-current-state.md#s16)).

**Read together with the Standard** ([`ai-software-factory/`](../ai-software-factory/README.md)). References written as "§n" point to this document; references written as "Standard §n" point to AISF Standard 4.0. The Standard defines vocabulary, governance and evidence, and this document never redefines them; where the two documents overlap, the Standard's text takes precedence. This document adds frontend detail and in some places is stricter ([§18.4](18-aisf-conformance.md#s18-4)). It is not looser, except for one declared deviation pending approval by the Standard's owner ([§18.1](18-aisf-conformance.md#s18-1)).
