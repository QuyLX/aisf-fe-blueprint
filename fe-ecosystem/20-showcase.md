# 20. Showcase plan

<a id="s20-1"></a>

## 20.1. Principle

The showcase MUST be demonstrated, not described. Each scenario below is a scripted, repeatable run (seeded PRs, fixtures, simulated incidents), executed on real repositories, and produces evidence bound to a commit, attested from the Phase 1a follow-up (the Slice 0 pilot portion uses CI artifacts, per the Minimum Viable Harness). This scenario set is also the **acceptance test suite of the Factory itself**: it reruns at every release of the policy repo, so a Factory change that breaks a guarantee is detected before rollout (Standard §7.15, item 5).

## 20.4. Showcase measurement

The showcase is evaluated against the baseline of the existing systems ([§16.2](16-current-state.md#s16-2)), per task class:

- lead time per work item (p50, p85) and human review time;
- change failure rate, revert rate and escaped defects;
- Cost per Verified Accepted Work Item;
- check false positive rate, flaky rate and bypass rate;
- test run time, selection miss rate and the rate of failures due to environment or test data;
- evidence coverage of critical journeys and traceability coverage;
- retrieval eval: finds the right source, the right version, cites correctly.

Success criteria are agreed after the baseline is measured. The stop criterion is a guardrail regressing for N consecutive weeks (Standard Appendix H). After each slice, a short **showcase report** publishes the results, the scenarios passed and any upstream proposals to the Standard (PC-7).
